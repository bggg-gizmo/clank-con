# Clank-Con v0.1.0 — device-test release

## User device evidence
User reported that the v0.0.2 diagnostic opened DuckDuckGo and they successfully signed in, but nothing happened in Clank-Con. This verifies external browser launch and external sign-in only. No built-in WebView sign-in, profile isolation, provider history enumeration or live capture is established. External browser and app private sessions are separate. The application now explicitly describes this boundary and accepts actual user-selected/shared text and files through Android's normal content transfer. A URL is not accepted as a full conversation. No password or session transfer, no provider access bypass.

User approved the production launcher icon: a robot taking notes. Native vector artwork is included in the APK. The source is independently authored; no third-party browser code was imported.

## Built application
- Package group.backgroundgremlin.clankcon; version 0.1.0, code 1; min API 28; target API 36. Separate package from both preserved probes.
- Eight provider destinations; two built-in persistent profiles; legitimate popup support, system autofill, explicit optional cookie compatibility, DuckDuckGo/default-browser options.
- Page-based CRT home/source/import/vault/search/results/review/branches/export/backup. Selection across paged results; paged long-text review; source metadata and original hashes; optional ZIP member expansion and image preview.
- User-supplied text/files, Android share and PROCESS_TEXT, direct-export temporary staging, encrypted vault; original bytes retained; duplicate original detection within provider/account/title/path.
- Known ChatGPT supplied JSON graph arrays streamed into separate records; branch explorer and derived branch records; metadata retained when explicitly present. Raw originals and archive members are preserved. Other provider archive formats are generic imports.
- Seven export implementations: TXT, PDF, JSON, Markdown, HTML, DOCX, ZIP. JSON and ZIP preserve original bytes; ZIP contains integrity manifest. Other formats render text and metadata, not embedded binary assets. End-to-end format tests remain outstanding.
- AES-256-GCM sequenced frames with authenticated terminal marker, Android Keystore vault key; portable passphrase-encrypted backups via PBKDF2-HMAC-SHA256 600,000 iterations; staged authenticated restore with conflict handling.
- No new Gradle, SDK, LFS, tool downloads, paid builds, external archival relay, telemetry or credential collection.

## Known limits and acceptance
No Android device attached in execution environment; user performs physical tests. No actual Android UI screenshot or runtime verification produced. Device-side Keystore, backup restore, import, PDF/document rendering and all exports require acceptance testing. Content search/text rendering limited to 16 MiB per original; graph parser has explicit per-graph character limit; larger original files retained as encrypted bytes and JSON/ZIP remain available. Generic ZIP expansion may partially succeed before a failed member; raw archive retained. Normal restore errors roll back; process termination during final move may leave a partial merge. No separate vault PIN or biometric lock. Temporary browser profiles, unlimited profile count, verified provider account identity, provider-specific capture adapters and live full-history retrieval (including archived/project conversations and server branches/attachments) remain outstanding. No scope removal or complete production release claim.
