# Clank-Con v0.1.0

Standalone Java Android archive application. This is a device-test release, not a provider-complete production release. The robot-taking-notes icon is an original native Android vector drawable. Previous diagnostics remain separate applications.

## Workflows

- Source: eight provider homepages; built-in persistent browser profiles A/B, user-gesture popup support, system autofill, optional per-window third-party cookies, DuckDuckGo/default-browser launch. Account label is local metadata, not verified provider identity. External login remains in the external browser; no cookie/token transfer.
- Import: share or select text using Android ACTION_SEND/PROCESS_TEXT, paste text, accept explicitly shared files, or choose one or many files via Android's system document picker. A URL alone is rejected as conversation content. Preserve each original file byte-for-byte; deduplicate matching account/provider/title/path/content. No automatic provider enumeration or extraction.
- Vault: Android Keystore AES-256-GCM authenticated 64 KiB frames, encrypted metadata and originals, local search and paged results. Direct-export mode uses an encrypted temporary directory that is discarded on successful export, explicit cancellation or next launch after interruption.
- ChatGPT JSON/ZIP: stream supplied arrays of conversation graphs into independent records; graph paths, branch endpoints, archived/project fields when explicitly supplied, timestamps, message roles and raw JSON preserved. All original archive files retained, with optional expansion of ZIP members (including images and attachments). Other provider formats can be imported as original text/files, not semantically parsed as verified provider conversation graphs.
- Review: paged text, image preview, source/hash metadata, branch exploration and derived branch records. Original graphs remain unchanged. Search/structured rendering has a 16 MiB per-original text limit; the original file remains intact and JSON/ZIP export is available. Large individual graph parsing has a 16 Mi-character limit with explicit failure. Archive expansion can partially succeed if a later entry fails; original retained. No disk plaintext for vault data. The vault does not implement a separate PIN or biometric lock.
- Exports: TXT, PDF, JSON, Markdown, HTML, DOCX, ZIP. JSON contains metadata and exact original bytes in base64. ZIP contains original files and SHA-256 manifest. Other formats render text and metadata; binary records are represented by metadata, not embedded. Text rendering of raw HTML is literal source rather than executing markup. Android PDF font/render fidelity, all format interoperability and full end-to-end flows require physical-device tests. Exports are plaintext files; use backup for encryption.
- Backup: password-encrypted portable archive, PBKDF2-HMAC-SHA256 600,000 iterations, random 16-byte salt, AES-256-GCM sequenced authenticated frames and end marker. Restore stages encrypted records, verifies manifest/hashes and the entire encrypted stream before merging. Conflicts are rejected. Normal restore errors roll back newly moved records; abrupt process termination during commit may leave a partial merge, and re-restoring matching IDs is supported. No password recovery.

## Direct build (no Gradle, no new SDK)

Supply extracted existing JDK 17, build tools r36 and Android API 36 `android.jar` paths. Use a locally managed signing keystore; never commit its private key or password. `build.sh` requires six positional arguments in this order: JDK directory, build-tools directory, android.jar path, output APK path, keystore path, key alias. Set the `CLANK_KEYSTORE_PASS` and `CLANK_KEY_PASS` environment variables through your local secure method before invoking the script. The script uses AAPT2, javac with UTF-8, D8, zipalign and apksigner, and verifies DEX SHA-1/Adler-32, expected classes, resources, alignment, signature, manifest and ZIP integrity. `test-host.sh` uses `JAVA_HOME` to compile and run the dependency-free encryption/framing and streaming parser host tests.

## Device acceptance

Install the APK alongside the diagnostics. Use synthetic sample data first. Verify launch, icon, page transitions and keyboard/rotation; select provider and open browser; confirm external login remains external; select actual conversation text and use Share or the Clank-Con text-selection action, or paste it into Import. Confirm URL-only share is rejected. Test file import, multiple selections, archive expansion, Unicode, branches, original-byte hash, duplicate handling, 7 exports, backup wrong password/tamper rejection and successful restore. Compare exported content and originals against the supplied input. Test browser A/B session isolation independently. Do not claim full provider retrieval based on an external login or test fixture.

## Outstanding scope

Live direct history discovery and retrieval, provider-specific account identity and capture adapters, verified archived/project/media coverage, temporary browser sessions, more than two browser profiles, provider-specific branch graph parsing outside ChatGPT supplied JSON, complete Android UI/runtime and export tests, large single-text search/rendering and a user-owned production signing setup. All remain project requirements. No credential extraction, no authentication bypass, no paid Actions, no LFS, no third-party engine downloads, no telemetry or external archival relay. No source from DuckDuckGo was copied; built-in browser uses native Android WebView and the previous independently written diagnostic components.
